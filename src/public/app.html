    Device access

    Permissions & connectivity

    WebGlow only requests microphone access for local LTC decoding. Display pages automatically request Screen Wake Lock and try a muted, nearly invisible video fallback if needed. This is best-effort: browser support, HTTPS, low-power mode, and operating-system policy can still affect it.

    If a microphone is missing

    1. Choose Request microphone access, approve both macOS and browser prompts, then choose Refresh inputs to reveal individually selectable devices.
    2. On macOS, check System Settings → Privacy & Security → Microphone and enable WebGlow, then restart it.
    3. Connect/enable the input in System Settings → Sound or Audio MIDI Setup, then refresh inputs. WebGlow can list only inputs exposed by macOS and the browser.

    For guest displays and WLED, allow WebGlow through the macOS firewall and keep the Mac and devices on a network that permits local device-to-device traffic. If you access the portal remotely, use HTTPS for browser microphone access.

    Audience layout

    Sections & live roster

    Guests select one of these sections when joining. The top-to-bottom order is the reference for left/right, front/back, diagonal, and center/edge effects. Arrange the names to match your room; use between 1 and 12 unique names.

    Guests are assigned evenly to virtual subsections within their chosen section, in registration order. This does not change the section they choose when joining.

    Portable show data

    Save or load a showfile

    A showfile contains cues and stacks, song/project timecode timelines, configured fixtures and their current output, plus audience-section ordering. Portal accounts, server/API settings, and registered guest lights are kept separate.

    Loading replaces this server’s cues, cue stacks, timecode timelines, configured fixtures, and section ordering. Existing guest registrations, portal access and server settings are preserved. WLED fixtures in the file may be updated.
